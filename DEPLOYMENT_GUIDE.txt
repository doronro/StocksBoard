DEPLOYMENT STEPS
================

Step 1: Prepare Database (Run in order)
------

1a. Create new database columns:

    ALTER TABLE users ADD COLUMN cash_balance NUMERIC(15, 2) DEFAULT 10000.00;

    ALTER TABLE orders ADD COLUMN idempotency_key VARCHAR(255) UNIQUE;
    CREATE INDEX idx_order_idempotency_key ON orders(idempotency_key);

1b. Verify columns were created:

    -- PostgreSQL
    \d users
    \d orders

    -- Should show:
    -- users: cash_balance numeric(15,2)
    -- orders: idempotency_key character varying(255)

1c. Set initial cash balance for existing users (optional):

    UPDATE users SET cash_balance = 10000.00 WHERE cash_balance IS NULL;

Step 2: Deploy Backend Code
----------------------------

2a. Update environment variables:

    # REQUIRED for production
    ENVIRONMENT=production
    SECRET_KEY=<generate-32-char-random-string>

    # Example SECRET_KEY (do not use this!):
    # SECRET_KEY=$(openssl rand -hex 32)

2b. Deploy code to production:

    git pull origin main

    # Or using Docker:
    docker build -t stocks-broker-api:v2 .
    docker push <registry>/stocks-broker-api:v2

2c. Run database migrations:

    alembic upgrade head

2d. Restart application services:

    systemctl restart stocks-broker-api
    # or
    docker-compose restart api

2e. Verify deployment:

    # Check logs for startup
    tail -f /var/log/stocks-broker-api.log

    # Should show:
    # "Application startup complete"
    # No "SECRET_KEY" warnings

Step 3: Verify Fixes (Run tests)
--------------------------------

3a. Run critical fixes test suite:

    cd /app/storage/tenants/...
    pytest tests/test_critical_fixes.py -v

    Expected: 16 passed

3b. Run full test suite:

    pytest tests/ -v

    Expected: All tests pass

3c. Smoke test API endpoints:

    # Test 1: Login with valid credentials
    curl -X POST http://localhost:8000/auth/login \
      -H "Content-Type: application/json" \
      -d '{"username":"testuser","password":"StrongPass123!@#"}'

    # Expected: Returns access_token and refresh_token

    # Test 2: Register with weak password (should fail)
    curl -X POST http://localhost:8000/users/register \
      -H "Content-Type: application/json" \
      -d '{"username":"newuser","email":"new@test.com","password":"weak"}'

    # Expected: 400 Bad Request with password validation error

    # Test 3: Create order (should validate buying power)
    curl -X POST http://localhost:8000/orders \
      -H "Authorization: Bearer <token>" \
      -H "Content-Type: application/json" \
      -d '{"symbol":"AAPL","side":"buy","quantity":1000,"order_type":"market"}'

    # Expected: 400 Bad Request if exceeds cash balance

    # Test 4: Refresh token (should verify user still exists)
    curl -X POST http://localhost:8000/auth/refresh \
      -H "Content-Type: application/json" \
      -d '{"refresh_token":"<token>"}'

    # Expected: Returns new access_token (or 401 if user deleted)

ROLLBACK PLAN (If needed)
=========================

If critical issues discovered after deployment:

Option 1: Quick Rollback (within 1 hour)
-------

1. Revert to previous version:

    git revert <commit-hash>
    git push origin main

2. Restart application:

    systemctl restart stocks-broker-api

3. Restore database (if schema changes):

    pg_restore -d stocks_db backup_before_deploy.sql

Option 2: Database Rollback (if schema changes failed)
------

1. Drop new columns:

    ALTER TABLE users DROP COLUMN IF EXISTS cash_balance;
    ALTER TABLE orders DROP COLUMN IF EXISTS idempotency_key;
    DROP INDEX IF EXISTS idx_order_idempotency_key;

2. Restore from backup:

    pg_restore -d stocks_db -c backup_before_deploy.sql

Option 3: Feature Flags (preferred long-term)

Implement feature flags for gradual rollout:

    BUYING_POWER_CHECK_ENABLED=true
    IDEMPOTENCY_KEY_ENABLED=true
    PASSWORD_STRENGTH_CHECK_ENABLED=true

    Can be disabled if issues found without code deployment.

SUPPORT TEAM NOTES
==================

Common issues and solutions:

Issue: User cannot register with password "Password123!"
Solution: Password needs special characters from !@#$%^&*()
Example: "MyPass123!@#" works

Issue: Order rejected with "Insufficient buying power"
Solution: User's cash_balance < (quantity * price)
   Action: Check user's available balance and order amount
   Verify: SELECT cash_balance FROM users WHERE id = user_id;

Issue: Refresh token returns 401 "User not found"
Solution: User account was deleted or deactivated
   Action: Have user log in again with fresh credentials

Issue: Order appears twice with same idempotency_key
Solution: Expected - client sent duplicate request
   Action: Idempotency prevents double-processing. No action needed.

Issue: Portfolio shows 0 closed positions when should show some
Solution: Positions must have status='closed' and quantity=0
   Action: Run migration and update position statuses
