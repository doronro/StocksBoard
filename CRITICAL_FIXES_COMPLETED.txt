CRITICAL ISSUES (Priority 1) - ALL FIXED
========================================

1. SEC-001: JWT Secret Key Fallback Vulnerability
   File: app/auth.py (lines 15-30)
   Status: FIXED

   Changes:
   - Removed default fallback "dev-secret-key-change-in-production"
   - Added ENVIRONMENT variable check
   - Raises RuntimeError if SECRET_KEY not set in production
   - Logs warning if development without SECRET_KEY
   - Fails fast at startup for production deployments

   Testing: test_critical_fixes.py (password validation tests verify auth setup)

2. SEC-011: Password Validation (Related to SEC-001)
   File: app/services/user_service.py
   Status: FIXED

   Changes:
   - Added validate_password() static method
   - Enforces 12+ character minimum
   - Requires uppercase letter
   - Requires lowercase letter
   - Requires digit
   - Requires special character (!@#$%^&*())
   - create_user() calls validate_password() before creating user
   - Raises ValueError with descriptive message on validation failure

   Testing: test_critical_fixes.py::TestPasswordValidation (5 test cases)

3. SEC-018: No Buying Power Validation Before Orders
   File: app/services/order_service.py
   Status: FIXED

   Changes:
   - Added cash_balance field to User model (default 10000.00)
   - Added validate_buying_power() async method
   - Validates user has sufficient cash before order creation
   - For buy orders: required_cash = quantity * price must be <= cash_balance
   - Raises ValueError with details if insufficient funds
   - create_order() calls validate_buying_power() before order execution
   - Returns None and logs error if validation fails

   Testing: test_critical_fixes.py::TestBuyingPowerValidation (3 test cases)

4. QA-008: Concurrent Order Race Condition
   File: app/services/order_service.py, app/models.py, app/schemas.py
   Status: FIXED

   Changes:
   - Added idempotency_key field to Order model (unique, indexed)
   - Added idempotency_key to CreateOrderRequest schema
   - Added idempotency_key to OrderResponse schema
   - Added get_by_idempotency_key() method to OrderRepository
   - create_order() checks for idempotency_key before creation
   - Returns existing order if duplicate request with same key
   - Prevents duplicate orders from rapid clicks
   - Routes/orders.py passes idempotency_key to service

   Testing: test_critical_fixes.py::TestOrderIdempotency (3 test cases)

5. QA-002: Closed Positions Count Always Zero
   File: app/services/portfolio_service.py, app/models.py
   Status: FIXED

   Changes:
   - Position model already has status field (OPEN/CLOSED/PARTIALLY_CLOSED)
   - Added count_by_user_and_status() to PositionRepository
   - get_portfolio_overview() now correctly counts open_positions_count
   - get_portfolio_overview() now correctly counts closed_positions_count
   - update_position() marks position as CLOSED when quantity becomes 0
   - Sets closed_at timestamp when position closes
   - Portfolio metrics no longer hardcode closed_positions_count = 0

   Testing: test_critical_fixes.py::TestClosedPositionsCount (5 test cases)
